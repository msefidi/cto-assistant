## Page contents (v26, 21 Sep 2026)

Two views, switched with the Overview / Cohort control in the header (state `view`, persisted in `localStorage` key `vj-view`; default Cohort). The sticky bar under the header holds the cohort selector with previous / next buttons (`#cohortPrev`, `#cohortNext`, `stepCohort(±1)`; ← / → keys also step when the focus is not in a form control) and the member count of the cohort. The whole bar is hidden (`hidden` attribute, `.filters[hidden]`) on the Overview. The country / Online-Hybrid / first-time chips and the Reset button were removed in v24 (Mahyar, 21 Sep 2026); `filtered()` is now the identity and `FKEYS` remains only for the heatmap's country split. The data date sits under the view switch.

**Overview view** (`#viewOverview`), eight sections. (A "Trends and patterns" card with computed bullets existed in v13–v17; removed in v18 on request, code parked in `archive/trends_bullets_v17.js`, to come back as board questions + answers.)

1. **New members per cohort** (`renderSizes`, `#sizeChart`): 25 bars, Sep–Nov in `--s1`, other months `--s1-soft`, value labels, tooltip with first-time/returning. Hint: Sep–Nov vs Jun–Aug average.
2. **Acquisition shares over time** (`renderOverview`, `#multi`, `.multi.six` = 3 columns): six small multiples, one per intent class except Mixed (Refresher-led, Webinar-led, On-demand accredited-led, SYFAT-led, On-demand-led, Unknown). Hint: first year vs second year shares.
3. **Revenue** (v26: one section, two stacked cards). Card 1 **Revenue by cohort and product** (`renderRevenueTrend`, `#revChart`, switch `#revMode` → state `revMode` y1 / all, default y1): 25 stacked bars, one per cohort, segments = the seven intent classes in `INTENTS` order (colour via `intentCol`, Unknown in `--axis`), value = year-1 fees (`fee1`) or all payments to date (`fee1+fee2+fee3`), EUR label on top (`eur`: €k / €M), y-axis in nice steps (10k … 1M). Tooltip: total, per member, year 1 vs later payments (all mode), per class € and share. Legend of the seven classes. Hint: totals to date, split by class, CME-led and Refresher-led share of year-1 fees first year vs second year of cohorts. Card 2 **Highest value and retention by profile group** (`renderBest`, `#bestValue`, `#bestValueHint`, `#bestValueFoot`, CSS `.rtab.best`, max-width 820px): Group-by switch (`.bestDimSwitch` → shared state `bestDim` spec / country / intent; the same control appears in section 8 and both stay in sync), then rank · group (dimension label, career stage below in muted) · members · year-1 renewal (number + `--s1` bar of 100%) · € per member years 1 + 2 (`fee1 + fee2`, number + bar relative to the largest group), sorted by value. 4. **Behaviour over time** (`renderBehaviourTrend`, `#behMulti`, switch `#behWin` → state `behWin` 30/90/365): five small multiples, one per behaviour category; shares are of members whose window has elapsed, hollow dot when the cohort is only partly observable. Hint: min–max across fully observable cohorts.
5. **Product reach over time** (`renderReachTrend`, `#reachMulti`, window switch shares `behWin` via `.winSwitch`): five small multiples, one per product family (`PRODUCTS`), share of observable members who used it in the window. Hint: first year → second year reach.
6. **Renewal and status by cohort** (`renderRenewTrend`, `#renewTrend`): year-1 renewal bars (hatched via `#hatch2` when `y1Complete` is false), active-today line + dots; tooltip has year 1, year 2, active, cancellation pending. Hint: first three vs latest three complete cohorts.

## Script layout

- `RAW`: the embedded rows (see contract below). `ROWS` maps them to objects; `MONTHS` is derived from the data; `AS_OF` (Date) and `AS_OF_LABEL` (text) are the data date; the label fills every `.asof` span and the template strings, so a re-extract needs only those two constants changed.
- `PANELS`: the six overview panels derived from `INTENTS` minus Mixed (Unknown drawn in `--muted` because `--surface-2` is invisible as a line).
- `INTENTS`: `[code, label, colour, definition]` for the seven intent classes (R W A S O M U), in display order. The definition is the hover text on the intent tiles (`defHover(boxId, defs, footer)`, attached once per tile box) and the `note` of the bar segments. Edit the wording there, and keep it consistent with the Definitions block.
- `PRODUCTS`: `[code, label, colour, definition, predicate(r, win)]` for the five product families used by the reach matrix and the reach-over-time panels.
- `WINDOWS` ({30, 90, 365} → label), `THRESH` ({win → [meaningful videos, active periods, period name]}), `MV_DEF` and `SEGMENTS`: `[code, label, colour, definition]` for the five behaviour categories (I Inactive, E Low/Episodic, L Live-only, D Digital-only, H Hybrid). The category is computed in `render()` from `l{win}` (attended), `v{win}` (meaningful videos) and `p{win}` (active periods), so changing a threshold needs no re-extract.
- Best members (v25/v26): `BEST_MIN`, `bestDim` state (two `.bestDimSwitch` controls kept in sync), `bestStat(rows)` (n, year-1 renewal, value = fee1 + fee2, active months, meaningful videos, attended-live share), `renderBest(rows)`.
- Money helpers (v23): `eur(n)` (€k / €M for tiles, labels and hints), `eurFull(n)` (full EUR for tables), `sum(rows, f)`, `feeAll(r)`, `intentCol(k)`; `revMode` state for the Overview switch.
- `render()`: on the Overview calls the overview renderers (sizes, acquisition, revenue, behaviour, reach, renewal, segments); on the Cohort view recomputes tiles, all five charts and the renewal-by-behaviour table for the selected cohort and active filters. `stackBar(id, segs, total, aria, W = 560)` draws one 100% bar (W = viewBox width, 900 in the matrix) (a segment may carry `text` to override its label, `pattern` for hatching); `stepBars(id, steps, total)` draws the checkpoint bars (hatched when `pending`). Tooltips on every mark via `showTip`.
- Cohort and view persist per viewer in `localStorage` (keys `vj-cohort`, `vj-view`), wrapped in try/catch.

### Row contract (`data/members_compact.json`)

`[cohort, country, type, kind, cycleYears, plannedExpiry, flags, intent, minutesToFirstLiveBooking, webinarBookings7d, courseBookings7d, meaningfulVideos30d, activeDays30d, meaningfulVideos90d, activeWeeks90d, meaningfulVideos365d, activeMonths365d, mvAccredited30d, mvSyfat30d, mvOther30d, mvAccredited90d, mvSyfat90d, mvOther90d, mvAccredited365d, mvSyfat365d, mvOther365d, liveMonthsMask, videoMonthsMask, monthsElapsed, stage, spec, fee1, fee2, fee3, tix, cvR, cvW]`

- `kind`: `f` first-time, `r` returning. `cycleYears`: 1 or 3. `plannedExpiry`: ISO date.
- `flags` bits: 1 active today · 2 active via B2B · 4 cancellation pending · 8 year-1 observable · 16 year-1 covered · 32 year-2 observable · 64 year-2 covered · 128 live booking in 7 d · 256 on-demand watch in 7 d · 512 Facharzt watch in 7 d · 1024 30-day window elapsed · 2048 attended live in 30 d · 4096 90-day window elapsed · 8192 attended live in 90 d · 16384 365-day window elapsed · 32768 attended live in 365 d · 65536 year-1 renewal was automatic · 131072 / 262144 attended a live course / a webinar in 30 d · 524288 / 1048576 same in 90 d · 2097152 / 4194304 same in 365 d. Next free bit: 8388608.
- `intent`: `R` Refresher-led, `W` Webinar-led, `A` On-demand accredited-led, `S` SYFAT-led, `O` On-demand-led, `M` Mixed, `U` Unknown.
- `minutesToFirstLiveBooking` is null when there was none in 7 days.
- `meaningfulVideos{30,90,365}d` and `activeDays30d` / `activeWeeks90d` / `activeMonths365d`: integers, 0 when none; see `docs/definitions.md`, behaviour categories.
- `mvAccredited/mvSyfat/mvOther{30,90,365}d`: the meaningful videos split by brand group; they sum to `meaningfulVideos`.
- `stage` / `spec` (v21, positions 29–30): profile segment codes. `stage`: `D` Doctor, `A` Assistant doctor, `X` other or empty occupation type. `spec`: `G` Allgemeinmedizin (incl. Praktische/r Arzt, Hausarzt), `I` Innere Medizin, `P` Psychiatrie, `K` Pädiatrie / Kinder- und Jugendmedizin, `C` Kardiologie (incl. Innere Medizin + Kardiologie listed together), `O` other single specialty, `M` several groups, `U` not stated. Source rule in `sql/cohort_member_rows_all_months.sql` (`prof` CTE) and `docs/data-pipeline.md`.
- `fee1` / `fee2` / `fee3` / `tix` / `cvR` / `cvW` (v23, positions 31–36): integers, EUR (CHF × 1.05), 0 when none. `fee1` = the cohort order total (net of promo codes, plus any upgrade order), `fee2` = the member's second paid B2C membership order (renewal of any kind, early renewal or re-join; membership not REVOKED / NOT_PAID), `fee3` = all later ones. `tix` = cash paid for course / webinar tickets after joining (member cash on top of credit + tickets bought as a non-member). `cvR` / `cvW` = `member_credit_value_eur` of live-course / webinar tickets after joining (list-price value covered by credit). Page fields of the same name. See `docs/definitions.md`, Money.
- `liveMonthsMask` / `videoMonthsMask` (v20): 12-bit integers, bit k−1 set when the member attended live / watched ≥ 1 meaningful video in member-month k (M1 = order date to order date + 1 month … M12 ends at the anniversary). `monthsElapsed`: how many of the 12 member-months had fully elapsed on the data date (0–12). Page fields `ml`, `md`, `mo`.

## Adding a section

1. Get the data into the row (see `docs/data-pipeline.md`), extend the `ROWS` mapping.
2. Add one `<section class="section">` with a `<div class="card">` after the renewal-by-behaviour section, before `<details>`.
3. Add the rendering inside `render()` using the existing helpers. Percentages use `pct(a, n)` against the filtered selection `n`.
4. Add a plain-language bullet to the Definitions block.
5. Update this file and `docs/log.md`.

Keep it lean: one finding sentence per topic, one chart, a plain-language definition. Mahyar removes anything that does not earn its place.

## Design rules

- Colours only via CSS tokens: `--s1` blue = cohort / observed / live / Refresher, `--c-low` light blue = Webinar, `--s3` aqua = today / active / on-demand accredited / digital, `--s2` orange = SYFAT, `--s5` purple = generic on-demand, `--s4` yellow = cancellation pending / mixed / hybrid, `--axis` mid grey = Low/Episodic, `--surface-2` grey = not a member / unknown / inactive / not yet observable (hatched). In small multiples, Inactive/Unknown are drawn in `--muted` and Low/Episodic in `--axis` because `--surface-2` is invisible as a line. Light and dark palettes are both defined on `:root`; never hard-code a colour in a chart.
- A legend whenever colour carries meaning; a tooltip on every mark; no dual axes; at most four coloured series per chart.
- Copy in English (the board deck is German; Mahyar translates the story). Numbers formatted with `fmt`, shares with `pct`.
- Works at phone width; the `.chart.narrow` class caps a chart at 620px inside a full-width card.
