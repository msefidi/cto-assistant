Set up on 30 Oct 2026 with Mahyar. Linear holds the current projects and issues; this note holds only the rules.

- **Track** (required, one per issue; also a project label group with the same values): Core product · Answer quality · Growth · Admin & analytics · Tech health · Product research and UX. ("Product" was taken by a workspace label, hence "Core product".)
- **Surface** (optional): Web app · Mobile app · Admin · Mixpanel · Website · App Store, each matching a title prefix (`Web:`, `Mobile:`, `Admin:`, `Mixpanel:`, `Website:`, `App Store:`). Use it only when the issue is bound to one surface; cross-surface work gets none and is split into sub-issues later. Never use the track as a prefix.
- **Naming:** issues are verbs, projects are nouns (outcome or topic), sentence case, "and" not "&". Bug fixes stay without a project.
- **Views:** roadmap = Mahyar's project view https://linear.app/fomf/projects/view/eviplex-b5e71e7aedfe; Watchlist (small but important items, workspace label "Watchlist") https://linear.app/fomf/view/watchlist-fadb0b618a63. Cycles are 2 weeks and start on Thursday.
- The Eviplex weekly (Friday mornings, Mahyar runs it) starts with the roadmap review of projects, then the Watchlist.

**Why:** Wafa kept opening a Word doc mid-meeting because Linear had no top layer (projects) and no way to follow small items.

**How to apply:** label new EVP issues with this scheme. The Linear MCP cannot create saved views; Mahyar builds them by hand. See [[linear-is-product-work]], [[eviplex-plan-memo-format]].
